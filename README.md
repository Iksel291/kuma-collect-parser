# Разбор диагностического коллекта KUMA

`parse-kuma-collect.sh` читает архив коллекта и показывает сводку хоста и ошибки служб KUMA. Рядом `kuma-log-errors.awk`: он разбирает строки лога и группирует одинаковые ошибки. `kuma-log-extract.py` достаёт из `logs.tar` только лог выбранной службы и останавливается, не читая хвост архива. Оболочка достаёт файлы сводки, рисует экраны и красит текст.

Версия в шапке: `parser 0.5.19`, подзаголовок «визуальные улучшения». Поднимайте `PARSER_VERSION` в начале shell-скрипта, когда меняется состав сводки, меню или группировка. Дописывайте строку в конец раздела «История».

Файлы скрипта — UTF-8, перевод строки LF, без BOM. CRLF в bash даёт `$'\r': command not found`.

## Запуск

Нужны bash, GNU tar, GNU awk и python3. На этой машине они в WSL. python3 читает лог службы из архива. Без него экран лога не открывается.

```bash
cd /mnt/c/Users/белоснежка/Desktop/collect_parser_for_kuma
./parse-kuma-collect.sh ./srv-kuma-46.adkaleks.loc-2026-11-13_16-20_collect.tar.gz
```

Из PowerShell, из папки проекта:

```powershell
wsl bash ./parse-kuma-collect.sh ./srv-kuma-46.adkaleks.loc-2026-11-13_16-20_collect.tar.gz
```

Путь `C:\...` скрипт сам переводит в `/mnt/c/...`, если его запустили внутри WSL. Функция `normalize_path`.

В терминале открывается меню. Без терминала (пайп, перенаправление) меню не рисуется и логи не читаются, пока не передан `--logs`.

| Ключ | Что делает |
|---|---|
| `--logs all` | все службы подряд, без меню |
| `--logs none` | только сводка |
| `--logs core,storage` | только эти роли, без меню |
| `--top 15` | только для `--logs`: сколько групп печатать. По умолчанию 10. В меню список всегда полный |
| `--include-warn` | добавить `warn` к `error`, `fatal`, `panic`, `dpanic` |
| `--out report.txt` | тот же текст без цветовых кодов |
| `--report` | первая страница в `<hostname>-report.txt` в папке, откуда запущен скрипт |
| `--report=all` | в тот же файл вся разобранная сводка и логи всех служб. Список групп не режется десяткой |
| `--color` / `--no-color` | цвет всегда или никогда. По умолчанию цвет есть, если stdout — терминал |
| `--keep-work` | не удалять временный каталог |
| `--debug FILE` | раз в секунду писать этап и память в FILE |

Проверка линейного пути, без меню: `--logs none` и `--logs storage`. Storage маленький, core — нет.

## Экраны

Меню живёт на запасном экране (`tput smcup` в `enter_ui`). При выходе `leave_ui` делает `tput rmcup`, выключает мышь и возвращает курсор. Ctrl+C тоже проходит через `cleanup`, иначе терминал останется в режиме мыши.

Пока список выше окна, его листают колёсико, стрелки и PgUp/PgDn. Колёсико работает, потому что скрипт включает отчёты мыши `\033[?1000h` и `\033[?1006h` (`arm_scroll`) и сам двигает окно. Запасной экран терминала прокрутки не имеет.

Ввод читает `read_ui_event` с `/dev/tty`, по одному символу, ключ `-N`, не `-n`. `-n` считает Enter концом строки и возвращает пусто, из-за этого выбор молча не срабатывал.

1. **Сводка** — `scroll_home` / `draw_home`. Одна рамка: хост и адрес, ОС, ядро и версия бинаря, затем CPU, load average и iowait из top, память, отдельно место по каждому монтированию с типом ФС (занято / всего, шкала, свободно), службы с id, при наличии `kaspersky/KESL` статусы модулей из `appinfo.txt` и проверка исключений папок KUMA из `expset.txt`, и меню логов. Пока имя или номер ещё набираются, подходящие строки меню подсвечены. Если в hostnamectl нет FQDN, имя красное и рядом предупреждение. `logs.tar` ещё не открыт. Номер или однозначное имя (`core`, `storage`, …) открывают роль сразу. `c` само по себе не выбирает: так начинаются `core`, `collector` и `correlator`. Enter нужен, только если набранное имя ещё подходит к нескольким ролям. `q` выходит.
2. **ID** — `scroll_id` / `draw_id_menu`. Даже если ID один. Номер открывает логи сразу. `b` возвращает к ролям, не читая лог. `q` выходит.
3. **Логи** — `show_logs` / `scroll_log_view`. Экран очищается, печатаются все группы ошибок этой службы. `b` — к ролям, `i` — к списку ID, `q` — выход. На этом экране дополнительно `j`/`k`. Enter не нужен.

Строка внизу показывает, какая часть списка видна (`строки 4–14 из 32`) и что можно нажать. Повторные перерисовки в `--out` не дописываются: первый кадр сводки пишется, дальше `SKIP_OUT=1`. Текст открытого лога в `--out` попадает один раз.

## Откуда берутся цифры

Префикс архива не зашит. На образце это `tmp/collect/`. Сводка достаётся одним проходом `tar` по маскам `SUFFIX_*`, без предварительного `tar -tzf`: оглавление большого gzip само по себе читает архив целиком. Потом `find_suffix` берёт самое короткое совпадение на диске.

| Файл | Что на экране | Кто читает |
|---|---|---|
| `environment/hostname.txt` | имя, ОС, ядро | `load_hostname` |
| `environment/ipa.txt` | IPv4, вывод `ip address`. Если файла нет, берётся `ifconfig.txt` | `load_ips`, иначе `load_ifconfig` |
| `environment/cpuinfo.txt` | число ядер и модель. Если файла нет, `hw.ncpu` из `sysctl.txt` | `load_cpu`, иначе `load_cpu_sysctl` |
| `environment/top.txt` | RAM, load average и `%wa`. Если строки памяти нет, `memory.txt` | `load_mem`, `load_top_pressure` |
| `kaspersky/KUMA/execvers.txt` | версия бинаря, на образце `4.6.1.54` | `load_version` |
| `environment/hdd.txt` | точка, устройство (`/dev/sda2`, `/dev/mapper/…`, `//сервер/шара`, бакет S3), тип ФС, свободно, занято и всего | `load_disks` |
| `kaspersky/KUMA/services.txt` | роль, статус, PID, ID. Файл пишет только Linux-ветка `collect.sh` | `load_services` |
| `kaspersky/KESL/appinfo.txt` | только активные компоненты KESL, английские и русские подписи. Блок есть, только если файл нашёлся | `load_kesl` |
| `kaspersky/KESL/expset.txt` | исключения папок KUMA. Если в коллекте файл назван `exset.txt`, читается он | `load_kesl_exclusions` |
| `kaspersky/KUMA/logs.tar` | ошибки одной службы, потоком, без копии файлов | `kuma-log-extract.py`, потом awk |

`expset.txt` пишет `kesl-control --export-settings`. В блоке KESL ищутся исключения папок: путь с каталогом `kuma` (`/kuma`, `/opt/kaspersky/kuma`, `/var/opt/kaspersky/kuma`) или сам каталог `/opt`. Выключенная секция не считается. Область сканирования и исключение чужой программы, даже если она лежит в `/opt`, папкой KUMA не являются. Найденные пути перечисляются, строка «исключения для KUMA добавлены» зелёная. Если таких путей нет, строка «исключения для KUMA не добавлены» красная.

`ipa.txt`: на экран попадает только IPv4. `lo`, адреса `127.0.0.0/8` и любые IPv6 не собираются.

`cpuinfo.txt`: логические ядра — число строк `processor`. Физические — уникальные пары `physical id` + `core id`. Если числа разные, пишутся оба. Рядом первая `model name`.

`top.txt`: числа берутся по словам `total`, `free`, `used`, `avail` со строки `(KiB|MiB|GiB) Mem`, а не по их порядку. Десятичный разделитель может быть точкой или запятой (`193119,8` и `193119.8` — одно число). Строка `Swap` в объём памяти не входит; с неё читается только `avail Mem`, если на строке Mem этого поля нет. `свободно` — это `free`, `доступно` — это `avail` (в нём ещё и отдаваемый кэш). Рядом с гигабайтами в скобках пишется целое число МиБ, чтобы его можно было сверить со строкой top. Старый procps (`total, used, free`), macOS `PhysMem` и FreeBSD `Mem: N Active` разбираются тем же `read_mem_awk`. `collect.sh` на Linux пишет ещё `memory.txt`; он используется, только если в top строки памяти нет. Из шапки top берутся load average (1, 5 и 15 минут) и `%wa`. Нагрузка на ядро — первая цифра, делённая на число логических ядер. Меньше 0.7 зелёная, от 0.7 до 1 жёлтая, от 1 до 2 красная («очередь»), выше 2 красная («перегрузка»). `%wa` меньше 10 зелёный, от 10 до 20 жёлтый, выше 20 красный.

`hostname.txt`: первая строка без двоеточия — имя. Дальше `ключ: значение`, английские и русские подписи. Имя из названия архива только для сверки. Если оно расходится с файлом, верным считается файл. Darwin пишет одну строку `hostname -f`, FreeBSD — одну строку `hostname`. FQDN — это Static hostname из hostnamectl, а если его нет, первая строка. Имя без точки, `localhost` или адрес — не FQDN: на сводке оно красное, под ним «FQDN не задан».

`services.txt` — склейка `systemctl status`, её пишет только Linux-ветка `collect.sh`, и только для юнитов, в имени которых есть `kuma-`. Новый блок — строка короче 400 символов, которая начинается с необязательного `●`/`○`/`*` и сразу `kuma-….service - описание`. Строка журнала вроде `Started kuma-….service - …` начинается с даты, поэтому службой не становится. Блок без строки `Active` и повтор того же юнита отбрасываются. `Active` режется по ` since `, `Main PID` — первое число, из `Loaded` берётся `enabled`/`disabled`. Подписи английские: коллект снят в локали C. Остановленный юнит из `systemctl list-units --all` остаётся в списке со своим статусом: это настоящая запись файла, не хвост журнала.

`hdd.txt` на Linux состоит из секций `mount:`, `df -h:`, `df -hi:`, `lsblk:`, `fstab:`, LVM. На Darwin и FreeBSD `collect.sh` пишет подряд `mount`, `df -h` и `df -hi` без заголовков секций. В отчёт идут постоянные ФС: ext2/3/4, xfs, btrfs, zfs, vfat, ntfs, apfs, ufs и похожие, а также сетевые `nfs`, `nfs4`, `cifs` и S3 (`s3fs`, `mount-s3`, `mountpoint-s3`, `goofys`, `geesefs`). `proc`, `sysfs`, `tmpfs`, devfs и squashfs спрятаны. У каждой точки одна строка: сначала устройство из `mount` (`/dev/sda2`, `/dev/mapper/…`, `server:/export`, `//сервер/шара`, бакет S3), затем каталог, тип ФС и три числа: свободно (колонка Avail), занято и всего. Десятичная запятая в `df` приводится к точке. Общей суммы по всем дискам нет. `/kuma` помечается «данные KUMA». Свободное меньше, чем «размер минус занято», из-за зарезервированных блоков.

Порядок ролей: core, collector, correlator, storage, metrics. Задаёт `role_rank`.

## Как идёт разбор

`main` одним проходом достаёт файлы сводки и вызывает `load_*`. `logs.tar` на этом шаге не открывается. Временный каталог в `/tmp`, а если `/tmp` — tmpfs, то в домашнем каталоге, чтобы гигабайты не оказались в оперативе. В конце `cleanup` его удаляет. `--keep-work` оставляет.

Дальше развилка:

- терминал и `--logs` не задан (`LOGS_MODE=ask`) — `ui_loop`;
- иначе `print_banner`, `print_host`, `print_version`, `print_disks`, `print_services`, `run_logs`. Это линейный отчёт для файла и пайпа.

`load_*` только заполняет переменные. Рисование отдельно. Общие поля хоста (IP, ядра, RAM) собраны в `emit_resources`: её вызывают и `print_host`, и `draw_home`. Диски и службы нарисованы дважды: `print_disks` / `print_services` для линейного отчёта и циклы внутри `draw_home` для меню. Новую колонку диска нужно добавить в оба места.

Экран сначала копится в массивы `VIEW_PLAIN` / `VIEW_DRAW` (`UI_CAPTURE=1`, пишет `view_put`). Потом `paint_rows` показывает только кусок, который влезает в окно. `wrap_into_screen` режет длинную строку по ширине терминала и не считает символы цвета за ширину.

Лог службы всегда лежит в её папке: `collector/<id>/log/`, `core/<id>/log/`, и так же для любой другой роли. Ролей в `logs.tar` может быть меньше или больше пяти. Чужой id и чужая роль не читаются: выбор metrics не разбирает collector, выбор collector не ищет лог в `core`.

`kuma-log-extract.py` открывает только `.../kuma/<роль>/<id>/log/`. До этой папки байты архива проматываются и не попадают в awk. После файлов этой папки чтение останавливается. Сырой лог на диск не пишется. Повтор того же id в этом запуске берёт готовый отчёт. Другой id начинает свой проход и тоже считает только свою папку. Сбой одного лога не закрывает скрипт. Ctrl+C во время счёта возвращает к меню. Каталог `logs/` в корне коллекта и `kaspersky/KUMA/journals/` не читаются.

В отладке сначала строка `проматываю до роль/id`, затем `считаю роль/id`. Имени чужой службы там быть не должно. Сам большой лог всё равно считается долго: это разбор его строк, не распаковка соседних папок.

Разбор одного лога: `analyze_service` вызывает awk, `render_log_protocol` читает ответ. В меню awk получает `TOP=all`, поэтому группы не обрезаются. В `--logs` действует `--top`, и если групп больше, последняя строка говорит, с каким `--top` перезапустить.

## Группировка ошибок

Правила живут в `kuma-log-errors.awk`. Тяжёлое не переносить в bash: core больше миллиона строк, цикл `while read` на нём занимает минуты.

Строка `info`, `debug` или `warn` (если warn не включён в рейтинг) не проходит `norm()` и разбор JSON. Считаются событие, уровень, период и поле `version`. Ошибки по-прежнему идут через `remember`. Этот короткий путь нужен, потому что на большом логе почти все строки не ошибки, а полный разбор каждой занимал минуты.

В нормализации после UUID длинный hex, в котором есть буква, заменяется на `<hex>`. Так id куска VictoriaMetrics не делает отдельную группу на каждую panic-строку. IP и обычные числа остаются как в логе.

Событие начинается с даты `2026-08-18T15:04:49.736Z`. Поля через табуляцию, две формы zap:

- `время  уровень  caller.go:N  сообщение  [json]`
- `время  уровень  имя логгера  caller.go:N  сообщение  [json]`

Caller — поле без пробелов, конец `.go:число`. Строка с датой, которую так не разобрать, увеличивает `не разобрано`. На этом снимке у каждой службы 0. Если счётчик вырос, смотрите сырую строку, а не группу.

Строки стека не начинаются с даты. Они не группы, их число — `кадров стека`.

Одна группа = уровень + файл исходника без номера строки + нормализованные сообщение и причина. Номер строки показывается отдельно: между сборками KUMA он едет.

Причина из JSON, по порядку: `error`, иначе `reason`, иначе `message`.

Порядок замен в `norm()` менять нельзя:

1. время → `<время>`
2. URL → `<url>`
3. UUID → `<id>`
4. hex длиной от 8 символов, если в нём есть буква → `<hex>`

IP и числа не заменяются: адрес и порт видны в строке группы.

URL раньше UUID. `query_id` в адресе ClickHouse сам UUID, и если заменить его первым, адрес рвётся. `destination '...'` в ключ группы не входит, а копится рядом: иначе одна недоступность рассыпается по назначениям.

`check health` (`client.go:205`) и `failed to do request` (`client.go:321`) — две строки одной проверки. Это разные места в коде, склеивать их не нужно.

Ответ awk — строки `STAT`, `ITEM`, `MORE`. Поля разделены символом `\036`, не табом. Таб для bash пробельный, пустая причина сдвигает колонки. Внутри awk ключ группы тоже не должен быть `SUBSEP`: индексы корзин сами используют разделитель.

Контрольные числа этого снимка, если разобрать все службы: core 215839 ошибки, collector 919, correlator 260, storage 77, metrics 87, везде `не разобрано` 0. У storage первая группа — `error checking schema`, причина `Post "<url>": dial tcp <ip>:<n>: connect: connection refused`, 25 раз.

## Куда править

**Новое поле сводки.** Суффикс в `SUFFIX_*`. В `main` добавить файл и в ветку каталога, и в `to_extract`. Функция `load_*` только читает. Поле хоста — в `emit_resources`, тогда оно появится и в меню, и в `--logs`. Отдельный блок — своя `print_*` для линейного отчёта и кусок `draw_home` для меню. Цвет — переменная в `setup_colors` и строка в таблице ниже. Логи в сводку не класть: их открывают третьим экраном.

**Цвета.** Одна палитра на все экраны. Текст `#D5DEE8`, второстепенное `#7D8B99`, акцент `#35C6D0`, успех `#39D98A`, предупреждение `#F0B44D`, ошибка `#F06464`, версия и пометка «данные KUMA» `#A78BFA`. В меню фон `#0B0F14`, выбранная строка `#161D26`. `running` зелёный, `failed` / `dead` красный, прочие состояния янтарные. Линейный отчёт красит текст теми же цветами и фон не меняет.

**Новый уровень или русский systemctl.** Уровни — `is_error()` в awk и `--include-warn`. Подписи `Loaded` / `Active` / `Main PID` — `load_services`. Образец берите из реального `services.txt`, не из памяти.

**Другая вложенность `logs.tar`.** Имя внешнего файла и кусок пути лога передаются в `kuma-log-extract.py` из `analyze_service` (`--outer`, `--needle`).

**Сжатый `collector.gz`.** tar кладёт его как есть, awk ждёт текст. Распаковывать до awk.

**Группы слишком крупные или мелкие.** Только `norm()` и сборка `key` в `remember()`. После правки прогоните `--logs storage` и `--logs collector`. core не трогать, пока маленькие не сойдутся с контрольными числами.

**Клавиши меню.** Общая читалка — `read_ui_event`. Когда номер уже однозначный, решают `number_ready` и `home_ready`. Экран ID повторяет это в `scroll_id`. Не возвращайте `read -n`: Enter снова пропадёт.

**Прокрутка.** Высота окна — `term_size`, рисунок видимых строк — `paint_rows`. Подсказка внизу своя у `paint_home_view`, `paint_id_view` и `paint_log_view`. Перед логом `ask_log_scope` спрашивает, что показать: только ошибки, только debug или всё. Отбор в `level_wanted`, архив заново не читается. На экране логов collector клавиша `c` открывает конфигурацию: JSON со строки `init`, список по имени и прокрутка готового текста.

## Чего скрипт не делает

- Системные логи из `logs/` и journald из `kaspersky/KUMA/journals/`.
- `df -hi`, `lsblk`, fstab и LVM. Файл `hdd.txt` для этого уже разобран по `mount` и `df -h`.
- Конфиги ClickHouse, MongoDB, `resources.json`.
- `warn`, если не передан `--include-warn`.
- Продукты в `kaspersky/`, кроме KUMA, статусов модулей KESL из `appinfo.txt` и исключений папок из `expset.txt`.

## История

- **0.5.19** — если установлен KESL, в его блоке проверяются исключения папок из `expset.txt` (`exset.txt`). Папка `kuma` или каталог `/opt` подсвечиваются зелёным, отсутствие таких исключений — красным.
- **0.5.18** — `--report=all` пишет в тот же `<hostname>-report.txt` всю разобранную сводку и логи всех служб. `--report` по-прежнему только первая страница.
- **0.5.17** — в блоке KESL остаются только активные компоненты. `--report` пишет первую страницу в `<hostname>-report.txt` в текущую папку.
- **0.5.16** — строки дисков выровнены по колонкам: устройство, каталог, тип и объём стоят друг под другом, даже если имена разной длины.
- **0.5.15** — сводка снова открывается: шкала диска больше не роняет скрипт при первом кадре.

- **0.5.12** — у диска рядом с каталогом показано устройство: `/dev/sda2`, `/dev/mapper/…` или имя шары. Сетевые `nfs` и `cifs` больше не отбрасываются.

- **0.5.10** — если в коллекте есть `kaspersky/KESL/appinfo.txt`, на сводке блок KESL со статусом каждого модуля. Работающий зелёный, остановленный жёлтый, недоступный по лицензии красный.

- **0.5.8** — рамка сводки стоит по центру экрана. Строки внутри рамки по-прежнему слева.

- **0.5.5** — сводка собрана в одну рамку: диагностика хоста, ресурсы со шкалой, службы и анализатор логов. Свободное место, все диски и предупреждение FQDN остаются. Клавиши те же.
